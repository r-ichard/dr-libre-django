# Plan: task 03, repeatable demo seed

Focal point: package `scheduling/demo_seed/` (what the demo world is, and how it is written
idempotently). The management command, one `.env.example` line, `compose.yaml` and the
`CLAUDE.md` checkout order are thin wrappers around it.

## One-sentence plan per block

1. **`scheduling/management/commands/seed_demo.py`**: refuses unless `settings.DEBUG`, reads `DEMO_PASSWORD` with `require_env`, takes the clock once (`timezone.now()`), calls `seed_demo(now, password)`, prints the counts.
2. **`scheduling/demo_seed/catalogue.py`**: frozen dataclass constants for the stable world: 3 hospitals, departments, rooms, specialties, appointment types, clinicians, availability, patients. No clock, no ORM.
3. **`scheduling/demo_seed/scenarios.py`**: frozen dataclass constants for the moving world: appointments, waitlist entries, time off, notifications, each placed by a day offset from "today" and a local time of day. No clock, no ORM.
4. **`scheduling/demo_seed/writer.py`**: `seed_demo(now, password) -> dict[str, int]`, one `transaction.atomic()`: upserts catalogue rows, then scenario rows, then writes the one audit entry. Callers above callees.
5. **`.env.example`**: one new line `DEMO_PASSWORD=...` (development value, labelled as published).
6. **`compose.yaml`**: `web` command becomes `sh -c "python manage.py migrate --noinput && exec python manage.py runserver 0.0.0.0:8000"`; `web` gets a `healthcheck` (python `urllib.request.urlopen` on `http://127.0.0.1:8000/api/v1/health`, since the slim image has no curl; `start_period` for the first migration).
7. **`CLAUDE.md`**: Fresh checkout order becomes `docker compose up --wait`, `docker compose exec web python manage.py seed_demo`, then the curl and the inbox; sandbox line gains `python manage.py seed_demo`.

## What identifies a seeded row, and what a later run does

All seeded addresses end in `@example.test`; all seeded codes start with `demo-`.

| Row | Identity | Later run |
| --- | --- | --- |
| Hospital, Department, Specialty, Room, AppointmentType | unique `code` (`demo-...`) | `update_or_create` by code: fields reset to the seed values |
| User | unique `email` | found by email; fields reset; password rewritten only if `check_password` fails (so no needless version bump); passwordless patient stays unusable |
| ClinicianProfile | its user | reset |
| AvailabilityRule | (clinician, weekday); `valid_from` is a fixed constant in the past | reset |
| TimeOff | (clinician, reason) | window re-anchored to the new today |
| Appointment | (patient, clinician, appointment_type), unique among seeded rows | **re-anchored**: `starts_at`, `ends_at`, status, source, room, cancellation fields reset, so day offsets always hold against the new today. Never recreated, never deleted. |
| WaitlistEntry | (patient, appointment_type) | window and status reset, links reset |
| Notification | (recipient, kind, appointment or waitlist entry) | created once; left as is (read state is user state) |
| AuditLogEntry | none, append-only | one new entry per run (so audit rows grow by one per run; that is the only count that changes) |

Rows a developer adds by hand are never touched (they lack the `demo-` code or the
`@example.test` address). A seeded row a developer edited is reset, except notifications.
No deletion: PROTECT references and the append-only log forbid it, and re-anchoring needs none.

**Why re-anchoring cannot hit the overlap constraints (the one real risk).** Updating row A into
the slot row B still occupies would raise inside the transaction (exclusion constraints are
immediate). Rule that prevents it: every seeded appointment sharing a clinician, patient or room
has a local time-of-day window disjoint from the others, with at least one hour between windows
(also covers DST). Windows never cross midnight, so any day shift is conflict free. A test pins
the rule by running the seed on days 1, 2, 3, 9 and 40 apart.

## Rules the seed keeps (deferred to use cases in the model plan)

- Clinician and type in the same department; room (appointment room, clinician default room, rule room) in the clinician's department; room only when `needs_room`, and an active room.
- `ends_at = starts_at + duration_minutes`; buffer is not added to the end.
- Appointment `patient` has role PATIENT; `clinician` profile user has role CLINICIAN; Hospital `time_zone` is an IANA name (`zoneinfo`).
- Today's, past and upcoming placement: offsets from the date in the hospital's own time zone, converted to UTC.
- Passwords: ADMIN, CLINICIAN and the one password patient use `DEMO_PASSWORD`; all other patients are passwordless with `email_verified_at` set (constraint `user_passwordless_has_verified_email`).
- Waitlist: OFFERED points at a seeded CANCELLED appointment (the freed slot); BOOKED has an Appointment whose `waitlist_entry` is that entry; WAITING and EXPIRED have none.
- Notifications: reminder only once per appointment; several `read_at` set, several null.
- Appointments are not forced into the clinician's weekly availability. Availability is Monday to Friday 09:00 to 17:00 and a seeded day may be a weekend. Stated, not fixed: no rule in the task needs it.

## World size

(`Australia/Sydney`, with coordinates). 2 departments each at least in one, rooms (one inactive
is not needed), types: with and without room need, online and not, one inactive. 5 specialties
(managed list; healthicons names are task-for-UI). About 5 clinicians, 6 patients, 12 to 14
appointments covering all 6 statuses and all 3 sources, 4 waitlist entries (all 4 statuses),
about 6 notifications (both read states, several kinds), 2 time-off rows.

Demo sign-ins: `admin@example.test` (ADMIN), `clinician@example.test` (CLINICIAN),
`patient@example.test` (PATIENT, password), `passwordless@example.test` (PATIENT, verified, no password).
Fake people: invented names, phones in the Ofcom drama range `+44 20 7946 0xxx`, no real
address, no real date of birth.

## Audit entry (section 4)

One `AuditLogEntry`: `actor` none, `action` `demo_seed.run`, `entity_type` `DemoSeed`,
`entity_id` `demo`, `correlation_id` a fresh UUID string, `metadata` = `{"rows": {"Hospital": 3, ...}}`:
model name to integer, nothing else. Written in the same transaction as the rows (§8). Rows
counted are the rows the seed owns, so repeat runs yield equal metadata.

## Invariants and blast radius

- Double booking: all appointments go through the three exclusion constraints; the seed never bypasses them, the disjoint-window rule keeps it conflict free.
- Authorization: none crossed; the command is a local developer tool that refuses outside `DEBUG`. The password is never in code, logs, audit metadata or the command output.
- Audit log stays append-only: the seed only inserts.
- Blast radius: new package and one command; compose `web` start-up changes (migrate first); no change to application code paths. A deployment with `DEBUG` off cannot seed.

## Trust boundaries

Environment: `DEMO_PASSWORD` absent gives `ImproperlyConfigured` (existing `require_env`), checked after the `DEBUG` check and before any write. Empty password refused (an empty `DEMO_PASSWORD` would publish an empty password). No user input, no request, no network. Time zone names validated implicitly by `ZoneInfo` raising on a bad name.

## Failing tests first (`returns_X_when_Y`, expected values in words)

Fixed clock, `settings.DEBUG = True` (pytest-django turns it off), password from `monkeypatch.setenv`.

- `returns_same_row_counts_when_command_runs_twice_on_one_day`: every model's count equals after the second run, except AuditLogEntry, up by exactly one; no exception.
- `returns_same_row_counts_when_command_runs_on_a_later_day` (days 1, 2, 3, 9, 40 later): same counts, no constraint error, and every seeded appointment's date moved with the day.
- `returns_past_today_and_upcoming_appointments_when_seeded`: at least one appointment ends before the clock, one has today's local date in its hospital's zone, one starts after it.
- `returns_every_appointment_status_and_source_when_seeded` and `returns_every_waitlist_status_when_seeded`: sets equal to the full enum values.
- `returns_read_and_unread_notifications_when_seeded`.
- `returns_two_time_zones_and_one_hospital_without_coordinates_when_seeded`.
- `returns_end_equal_to_start_plus_duration_when_seeded`, `returns_same_department_for_clinician_type_and_rooms_when_seeded`, `returns_roles_clinician_and_patient_when_checking_appointment_people`, `returns_booked_appointment_linked_to_entry_when_waitlist_entry_is_booked`.
- `returns_true_when_demo_account_checks_the_environment_password` for admin, clinician, patient (`check_password`; the sign-in use case does not exist yet, task 05, so password check is the available proof); `returns_false_when_another_password_is_checked`.
- `returns_unusable_password_and_verified_email_when_account_is_the_passwordless_patient`.
- `returns_new_hash_only_when_password_in_environment_changed`: unchanged run keeps `version`; changed password authenticates after next run.
- `returns_only_example_test_addresses_and_reserved_phones_when_seeded`.
- `raises_command_error_and_writes_nothing_when_debug_is_off`: `CommandError`, zero rows in every model.
- `raises_error_and_writes_nothing_when_demo_password_is_missing_or_empty`.
- `returns_audit_entry_with_only_integer_counts_when_seeded`: one entry per run, `metadata` keys exactly `rows`, every value an integer, a count for every seeded model; serialised metadata contains no seeded name, email, phone.
- `returns_unchanged_manual_row_when_seed_runs_again` (a hand-made hospital survives untouched).

Red-for-right-reason: the tests fail on `CommandError: Unknown command: 'seed_demo'` / missing import, not on a typo.

## Domain entities used

Hospital, Department, Specialty, Room, AppointmentType, User (Admin, Clinician, Patient), ClinicianProfile, AvailabilityRule, TimeOff, Appointment, WaitlistEntry, Notification, AuditLogEntry. Not used: Session, BookingHold, VerificationCode, SignInLink, ApiClient (no model yet).

## Will not do

No view, use case, serializer, admin, fixtures file (JSON fixtures cannot be relative to the run day), new dependency, factory library, settings change, model change, deletion of old seeded rows, a `--reset` flag, a `--password` argument (would land in shell history), or Docker verification here (the sandbox cannot run it; orchestrator verifies item 6 on the host).

## Open points

1. The Compose healthcheck probes with Python because the image has no curl; adding curl to the image would be a Dockerfile change.
2. Re-anchoring resets developer edits to seeded appointments on each run; chosen over "leave alone" because past/today/upcoming must hold on a later day.
3. DST: a re-anchored local time on a DST transition day shifts by an hour in UTC; the one-hour gap rule absorbs it.

## Architect review

Verdict: approve.

- Ladder: smallest fit. No dependency, no model or settings change, no factory library. Three data modules plus one writer is justified by the pure-versus-ORM split (§8), not speculation.
- Each block states one purpose; vocabulary matches CLAUDE.md.
- Tests named as behaviours with expected values, first red proven for the right reason. They cover the later-day shift (1, 2, 3, 9, 40 days), DEBUG off, missing or empty password, audit holding only counts, and an untouched manual row.
- Security: DEBUG check comes before the password read and before any write. No `--password` flag. The password stays out of code, logs, audit metadata and output. Audit insert only, in the same transaction.
- Identity and re-run rules per row are explicit. The disjoint-window rule against exclusion-constraint conflicts is stated and tested.
- Scope: items 1 to 7 are all covered. Docker verification is left to the orchestrator, as the task says.
