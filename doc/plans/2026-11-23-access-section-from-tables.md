- `### API (/api/v1)`: one table, 30 rows. Columns: Method, Route, Visitor, Patient, Clinician,

  `` - `GET /api/v1/...`, visitor, own record: table 401, product 200 ``. A `|` in any cell is

## Architect review

Verdict: revise. Scope and ladder are sound: item 4 only, stdlib script, no new abstraction, no product
behaviour change. The points below must be fixed in the plan before generation.

1. **Makefile command cannot import the tables.** `uv run python scripts/access_table.py` puts `scripts/`
   on `sys.path`, not the repo root. `pyproject.toml` has no `[build-system]`, so `scheduling` and
   `test_support` are not installed. Pytest works only because `pythonpath = ["."]`. Name the working
   form (for example `uv run python -m scripts.access_table doc/security-review.md`, or an explicit
   `sys.path` insert of the repo root in the script) and say which one the green test proves.
2. **Wrong expected count.** The API table has 27 rows (`API_ACCESS_ROWS`, counted by import), not 30.
   The test "one data line per row (30 API ...)" would fail on the real tables. Page total is 113 by
   import, not "about 118". Fix both figures.
3. **Page KNOWN_DIFFERENCES have a different shape.** The page value is `dict[(route, caller)] ->
   (Answer, str)`, where the product answer is a string such as `302 /patient/`, not an HTTP status.
   The bullet format given (`table 401, product 200`) does not fit pages. Specify the page bullet.
4. **API known-difference record field is unspecified.** `KnownDifference.record` is `RecordUse | None`.
   The bullet example says "own record" but the plan does not say what renders for `None` or `other`.
   Specify it. The API table itself has no record column; say so, since the walk's own/other split
   would otherwise be invisible in the document.
5. **Missing first tests for error and edge paths (§10).** No test for: `## Access` absent, `## Access`
   twice, a section with no following `## ` line (runs to end of file), and `|` escaping in a cell. Each
   needs an expected behaviour: raise on a broken document is the §9 rule for invariant breaks, so state
   it and test it.
6. **Renderer discovery of page tables is not stated.** Test 4 says each module-level `Row` tuple is
   "one the renderer uses, matched by identity". Say whether the renderer enumerates the modules (by
   `vars()` over the glob) or uses a fixed list. Only the first makes that test catch a forgotten table.
7. **FHIR caller type undefined.** `FhirKnownDifference.caller` has no type: there is no FHIR `Caller`
   enum. The FHIR column "Visitor" is labelled "no token" in `fhir_access_rows.py`. Pick one label and
   say which type `caller` is.
8. **Tokens.** Task 26b3 item 1 names "a token of each role". The API and page tables have no token
   column; FHIR's "no token" is the only token-like column. Say in one line that tokens are the
   FHIR caller and not rendered for API, or that they are out of this section.

Not reasons to revise: the FHIR empty `KNOWN_DIFFERENCES` and its dataclass (acceptable; the renderer
reads it), the single page table (matches "one table per surface"), the untouched review lines 12 and
180 (brief says nothing else changes; orchestrator decides).
