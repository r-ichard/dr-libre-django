### #33 P1: Clinician form answers 500 for a round robin weight above 32767

#### Summary
The clinician create and edit forms in the admin console answer HTTP 500 when the round robin weight is above 32767. The field has no upper bound in the form, so the database rejects the value (`DataError`).

#### Steps to reproduce
1. `docker compose up --wait`, seed the demo, sign in as `admin@example.test`.
2. Open `/admin-console/clinicians/<id>/edit` for any clinician.
3. Post the form (valid token, `Origin` set) with `round_robin_weight=32768` (also `2147483647`, `99999999999` on `/admin-console/clinicians/new`).
4. Compare with `32767`, which saves.

#### Observed
HTTP 500, our error page with a reference. `scratch/qa/server.log` holds `"message": "unexpected error"` with exception type `DataError`. Nothing saved.

#### Expected
A validation message on the field, as rooms and appointment types give ("Use a whole number of at most 32767"). Section 4: validation at every boundary; expected failures are results (`invalid_input`), not crashes.

#### Evidence
Reproduced as second reader: edit post with `32768` gave 500, reference `26129761a0c1450390aa2fef6767e38c`, server log `DataError`; the stored weight stayed 1.

### #38 P1: NUL byte in a clinical note or a time-off reason answers 500

#### Summary
A NUL byte (`%00`) in the clinical note or in the time-off reason makes the server answer 500. PostgreSQL refuses NUL in text and the `DataError` is not turned into a validation result.

#### Steps to reproduce
1. Sign in at `/sign-in` as `clinician@example.test` with `DEMO_PASSWORD` (CSRF token + `Origin: http://127.0.0.1:8000`), keep the cookie jar.
2. Pick one of the clinician's own appointment ids (here `<ID>`), `CT` = the `csrftoken` cookie value:
```
curl -s -b jar -o /dev/null -w '%{http_code}\n' -H 'Origin: http://127.0.0.1:8000' \
  --data "csrfmiddlewaretoken=$CT&clinical_notes=a%00b" \
  http://127.0.0.1:8000/clinician/appointments/<ID>/notes
curl -s -b jar -o /dev/null -w '%{http_code}\n' -H 'Origin: http://127.0.0.1:8000' \
  --data "csrfmiddlewaretoken=$CT&starts_at=2027-01-01T10:00&ends_at=2027-01-01T11:00&reason=a%00b" \
  http://127.0.0.1:8000/clinician/time-off
```

#### Observed
Both answer `500`. `server.log` has `"message": "unexpected error"`, exception type `DataError`, routes `clinician/appointments/<uuid:appointment_id>/notes` and `clinician/time-off`. The cancel reason handles the same byte (422), so the field checks differ.

#### Expected
Section 4: every input validated, expected failures are results, not crashes. Answer 422 with a field message, as for an over-long note.

#### Evidence
Reproduced twice (by the first tester and by the verifier): `500`, `DataError` lines in `scratch/qa/server.log`.
