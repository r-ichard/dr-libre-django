2. **Low**, `ADR 0003` "Not covered", `Appointment.inherited_version`. Nothing in the database ties `inherited_version` to the entry's final `version`; a use case can write a wrong number and `versionId` could fall or repeat. Risk: wrong `ETag` once the accept use case exists. Fix: the accept use case task must set it from the locked entry in the same transaction, with a test.

4. **Low**, `models/base.py:55-70`. `save()` restores `version` on `DatabaseError`, but a successful save on a row deleted meanwhile raises inside Django as `DatabaseError` too, indistinguishable from a stale write. Risk: the later `If-Match` path uses the filtered `update`, not `save`, so no impact now. Fix: when the API task lands, use the `update(version=expected)` row count, not `save`.
5. **Low**, test suppressions `test_version.py:38,84`, `test_waitlist_resource.py:77` are `# type: ignore[code]`, allowed by §7 (named). Typed helpers would be cleaner. Fix: optional.
